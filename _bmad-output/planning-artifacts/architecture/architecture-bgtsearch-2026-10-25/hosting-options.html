Hosting bgtsearch for (almost) nothing

Options compared for v1 · checked 25–26 Oct 2026 · companion to ARCHITECTURE-SPINE.md

Chosen: €0/month. GitHub Actions runs the collector 4× a day, commits the data into the repo, builds the site, and deploys it to GitHub Pages. Nothing runs when someone visits. The only optional cost is a custom domain.

How it runs

1 · ScheduleGitHub Actions cron, 05:17 / 11:17 / 17:17 / 23:17 UTC
2 · CollectFetch ~55 centre sites politely, parse KuferWeb and ITEM KG pages
3 · RememberMerge with history in data/, commit to the repo
4 · PublishBuild the Preact site + one JSON snapshot, deploy to Pages
5 · VisitBrowser loads static files; search and distance run on the phone

Plan B for each risk

  • A site blocks GitHub's IPs: a home machine (e.g. a Raspberry Pi) runs the pipeline on a cron and pushes the data with a limited token; GitHub still deploys. Not a self-hosted GitHub runner: on a public repo, anyone's pull request could run code on your home machine.
  • GitHub disables the cron after 60 quiet days: every run commits fresh data, which should count as activity, but GitHub doesn't define the term. A free dead-man check alerts you if no run arrives for 13 h; re-enable the workflow in the Actions tab.
  • A reader breaks: its centres keep their last dates, marked stale, and any failed run opens a GitHub issue, which emails you.
  • GitHub's Actions terms: scraping on GitHub's runners is fine while it is the repo's own purpose, but it's a grey zone; the home fallback covers it.
  • v2 alerts need a backend: Cloudflare Workers Paid ($5/month) is the natural next step; the git history is the data source.

What still costs money or effort

  • Custom domain (optional, yearly fee). The free *.github.io address works for the private beta.
  • Impressum and privacy policy before public launch: needs a named operator with a postal address, and the policy must say GitHub Pages hosts the site and sees visitor IPs.
